# Orvia

AI receptionist for service businesses. Orvia answers every call, books
appointments into the business's calendar, captures leads, and hands the owner
a dashboard of everything that happened.

- **Voice:** Vapi (LLM + TTS + STT), phone and in-browser calls
- **Backend:** Supabase (Postgres + RLS, Edge Functions, pg_cron, Realtime)
- **Frontend:** React 19 + Vite + TanStack Router / Query
- **Integrations:** Google Calendar (OAuth), Twilio SMS

## Getting started

```bash
npm install
npm run dev        # http://localhost:30001
```

Create `.env.local` (git-ignored):

```bash
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon key>
VITE_VAPI_PUBLIC_KEY=<vapi public key>   # fallback; the Admin key vault takes priority
```

`npx tsc --noEmit` type-checks the app. `src/routeTree.gen.ts` is generated by
the TanStack Router Vite plugin — restart the dev server after adding a route.

## How a call works

1. A caller dials the business number (or clicks **Talk to Assistant** in the
   dashboard for a browser test call).
2. Phone calls: Vapi asks `assistant-request` for the assistant. Browser
   calls: the dashboard builds the same config in `src/lib/vapi/build-assistant-config.ts`.
   The system prompt is assembled per call from the business's settings and
   its niche playbook (`src/lib/vapi/niche-profiles.ts`).
3. During the call the AI uses three tools:
   `check-availability` → `book-appointment`, or `capture-lead`.
4. `vapi-events` receives status updates and the end-of-call report
   (transcript, summary, duration) and writes the `calls` row.

### Edge functions

| Function | Called by | Purpose |
|---|---|---|
| `assistant-request` | Vapi (phone) | Returns the assistant config for the called number |
| `check-availability` | Vapi tool | Open slots from hours, bookings and Google Calendar busy times |
| `book-appointment` | Vapi tool | Creates the appointment, Google Calendar event and SMS confirmations |
| `capture-lead` | Vapi tool | Saves a callback request and texts the owner |
| `vapi-events` | Vapi webhook | Call lifecycle + end-of-call report, billing deduction |
| `demo-call-token` | Dashboard | Short-lived token so browser test calls can use the tools |
| `google-oauth-start` / `-callback` | Dashboard / Google | Connect a Google Calendar |

**Webhook auth** (`_shared/vapi-auth.ts`): requests are accepted with Vapi's
`x-vapi-secret` header, a legacy HMAC `x-vapi-signature`, or a demo token
(`x-orvia-demo-token`, 30 min, scoped to one business). All Vapi-facing
functions are deployed with `verify_jwt = false` and do their own auth.

### Edge function secrets

```
VAPI_WEBHOOK_SECRET        GOOGLE_CLIENT_ID      GOOGLE_CLIENT_SECRET
TWILIO_ACCOUNT_SID         TWILIO_AUTH_TOKEN     TWILIO_FROM_NUMBER
OWNER_PHONE (fallback)
```

Google OAuth redirect URI: `https://<project-ref>.supabase.co/functions/v1/google-oauth-callback`.

## Scheduling modes

Settings → Business → **Scheduling**:

- **Live** — checks real opening hours, existing bookings and the connected
  Google Calendar; new bookings are written to that calendar.
- **Simulated** — demo mode: the AI always finds open slots; bookings land in
  the dashboard only.

## Admin tools

Visible only to `role = 'admin'` users (enforced by RLS / `SECURITY DEFINER`
checks, not just the UI), under **Admin · Internal** in the sidebar:

| Page | What it does |
|---|---|
| **Demo Niche** | Switch the account between Dental, Plumbing, HVAC, Real estate and Customer support. Swaps business details and the AI's call playbook, and regenerates matching demo data. |
| **Users** | Every login across all businesses, with role, status and last sign-in. |
| **Demo Data** | Toggle daily autofill, generate a batch now, or clear all demo data. |
| **Model Config** | Override the LLM, voice and transcriber; preview the exact system prompt. |
| **Vapi Accounts** | Vault of Vapi keys with manual balance tracking; pick the active one. |

### Demo data

Generated calls are tagged `extracted_data.demo_seed = true` and never touch
billing. With autofill on, `pg_cron` runs `run_demo_autofill()` at 07:30 and
14:30 UTC, adding a few calls (with full transcripts, appointments, leads and
Needs Attention alerts) and pruning anything older than 35 days. To remove
everything: **Admin · Demo Data → Clear all demo data**.

## Deploying

- **Frontend:** Vercel (set the `VITE_*` env vars there).
- **Database:** apply `supabase/migrations/*` in order.
- **Edge functions:** `supabase functions deploy <name>`; Vapi-facing
  functions need `--no-verify-jwt`. Include `supabase/functions/_shared`.

> The deployed `assistant-request` (phone calls) predates the niche playbooks
> in this repo. Redeploy it before connecting a live phone number.
